# Doubao Voice Bridges

两个配合豆包语音输入法使用的 macOS 菜单栏工具：用耳机线控控制本地豆包听写，以及通过网易 UU 远程把本地转写的文字粘贴到远端 Mac。

| 工具 | 当前版本 | 作用 |
| --- | --- | --- |
| [豆包耳机语音桥接](apps/headset-bridge/) | 1.2 / build 3 | 在本地发送约 60 毫秒 Fn / Globe 脉冲；UU 前台时向远控桥接请求开框 |
| [UU 远控听写 Fn](apps/uu-voice-bridge/) | 2.5.1 / build 11 | 接收 Fn 或耳机开框请求，在本地发送框收集文字，通过 UU 剪贴板同步发送到原远端窗口 |

两个工具均可单独使用；同时使用时，请配套更新到上述版本。桥接程序不录音、不提供语音识别服务、不自行联网；录音和转写由豆包完成，远程连接和剪贴板同步由 UU 完成。

## Fn 与线控的分工

| 当前使用位置 | 按键 | 预期操作 |
| --- | --- | --- |
| 普通本地输入框 | Fn | 交给豆包自己的 Fn 设置处理 |
| 普通本地输入框 | 线控中间键 | 耳机桥接发送短 Fn，交给豆包处理 |
| UU 连接窗口 | 第一次 Fn | 打开本地发送框 |
| UU 连接窗口 | 第一次线控点击 | 通过两个桥接程序之间的本机消息打开发送框，不同时发送 Fn |
| 本地发送框内 | 再按 Fn 或线控 | 交给豆包开始或结束听写；文字落在发送框 |
| 本地发送框内 | Return | 把文字发送到原 UU 目标窗口 |

如果希望“按一下开始、再按一下结束”，请在豆包中选择相应的 **Fn 免按模式**，并先在普通本地输入框中验证。耳机发送短 Fn，不能代替豆包要求的持续按住操作。实际 Fn 识别仍受豆包版本、快捷键设置及其他监听工具影响。

## UU 远程 Mac → Mac 的操作

1. 确认豆包在普通本地输入框内可以用 Fn 听写；确认本地复制的文字能在远端 Mac 手动粘贴。
2. 在 UU 连接窗口中点击远端需要输入文字的位置，从「远控听写 Fn」菜单启用听写。
3. **按一次 Fn 或点击一次线控中间键，打开本地发送框。**
4. 框内再按 Fn 或线控开始豆包听写；按豆包设置的方式结束，确认文字出现，可继续编辑。
5. **按 Return 发送**。Esc 取消；输入法仍有候选或标记文本时，按键先交给输入法处理。

请等发送框出现并获得焦点后再按第二次；耳机开框确认到达前的极快第二次点击会被忽略。

发送框由本工具创建，并非 UU 自带的剪贴板面板。第一次按键只开框，后续 Fn 也不代替 Return 发送。已有草稿时，再从同一 UU 进程和原窗口开框会恢复原草稿，不清空文字、不更换发送目标。

默认首次 Fn 即使长按也只开框。需要旧的长按录音、松开后尝试自动发送流程时，可开启菜单「兼容模式：长按 Fn 直接听写」，然后重新启用监听。该路径依赖合成 Fn 和输入法焦点切换，需单独实测。

## 构建和安装

在 macOS 上安装 Xcode Command Line Tools。构建两个工具需要 macOS 13 或更新版本，以及支持 Swift 5.9 或更新版本的工具链；耳机子项目本身的最低目标系统为 macOS 12。无第三方包依赖。

在仓库根目录执行：

```sh
bash scripts/test.sh
bash scripts/build.sh
```

生成的应用分别位于：

- `apps/headset-bridge/dist/DoubaoHeadsetBridge.app`
- `apps/uu-voice-bridge/dist/远控听写 Fn.app`

两个应用均包含 Apple Silicon 和 Intel 架构。构建脚本只生成产物，不安装或启动菜单栏应用。先退出旧版，再把应用放到固定位置，例如「应用程序」，每个工具只运行一份。

应用使用 ad-hoc 临时签名，没有 Apple 开发者身份签名或公证。可自行构建；对可信构建，按 macOS 提供的「隐私与安全性 → 仍要打开」流程处理，无需关闭系统安全机制。

UU 工具需要「辅助功能」和「输入监控」，每次启动默认暂停，授权后需手动启用。耳机工具需要辅助功能来发送按键；独占打开匹配的线控接口还可能需要输入监控，以实际接管结果为准。豆包另行获得麦克风权限。详见 [隐私与权限](docs/privacy-and-permissions.md)。

## 支持和验证范围

- 目标链路为本地 Mac → UU → 远端 Mac，要求 UU 文字剪贴板同步可用；不宣称 Windows 远端兼容。
- 耳机工具只匹配 `Product=Headset`、`Transport=Audio`、消费者用法页 `12`、主用法 `1` 的接口，不覆盖所有 3.5 mm、USB 或蓝牙耳机。
- 两个桥接通过本机消息协调第一次线控开框，避免这一操作与豆包同时争用合成 Fn。开框没有收到确认时会提示失败，不补发 Fn，避免迟到开框后误触发录音。
- Fn 监听采用实际 Fn / Globe 修饰键事件，键码为 `63`。进入 UU 时允许一次有条件的监听刷新；不是持续抢占其他监听器，系统停用监听时仍会暂停。安全输入、第三方监听顺序及软件版本差异可能影响触发。
- 发送覆盖并保留系统剪贴板。程序只确认本机粘贴指令已发出，不能确认远端实际收到文字。发送期间保持 UU 目标窗口有效，避免切换焦点或改写剪贴板。

根测试脚本运行纯逻辑测试；macOS CI 配置运行相同测试及双架构构建。额外的 AppKit、事件构造和隔离剪贴板自检需有图形桌面的系统会话。上述检查不能替代真实耳机、豆包录音、进程间协作和双机验收，也不构成所有环境无冲突的保证。

测试范围和手工检查清单见 [耳机验证说明](apps/headset-bridge/docs/validation.md) 与 [UU 验证说明](apps/uu-voice-bridge/docs/validation.md)。遇到授权无效、没有文字或无法远端粘贴时，按 [排错说明](docs/troubleshooting.md) 逐步定位。
