# 验证范围

## 2.5.1 / build 11：Fn 与耳机协作

本次在 2.5.0 基础上修改了监听生命周期、首次 Fn 的默认行为、耳机开框请求及草稿恢复。不能直接沿用 2.5.0 的构建或功能验收结果。

测试目标包括：

- 既有安全检查：Fn 开框、按键来源区分、Home 不接管、进程锁等。
- 监听策略：物理松开后恢复、发送框交接、进入 UU 刷新的空闲条件、冷却及停止流程。
- 协作协议：请求字段与时效校验、去重、确认结果，以及只能恢复原进程和原窗口的草稿。
- arm64 / x86_64 Release 编译、通用二进制、Info.plist 与全部架构 ad-hoc 签名校验。

本次已通过：

- 根目录 `bash scripts/test.sh`：UU 95 项纯逻辑检查；耳机 35 个映射场景、21 项解码检查和 43 项协作路由断言。
- UU Debug 完整自检：9 组基线检查、16 项 Fn 检查、8 项隔离剪贴板检查、95 项安全检查。
- 隔离的真实双进程通知测试：复用当前服务端源码，替换通知对象为测试专用名称；发送相同 UUID 的两次请求，收到两次确认，开框回调只处理一次。测试未创建实际发送框、未注入系统按键，也未影响在用应用。

```text
LOGIC_SELF_TEST_OK safety_cases=95
SELF_TEST_OK baseline_groups=9 fn_cases=16 clipboard_cases=8 safety_cases=95
```

Release 双架构构建、完整自检和签名校验均已通过。已安装应用的暂停启动检查通过（`PAUSED_STARTUP_OK own_event_taps=0`）。完整界面的进程协作、实际启用后的监听生命周期、实体 Fn / 线控、豆包录音及双机粘贴仍需按下方清单实测；逻辑检查及隔离通知测试不能替代这些验收。

## 如何运行检查

```sh
zsh scripts/test.sh
zsh scripts/build-app.sh
```

默认运行纯逻辑检查。图形桌面会话可额外执行：

```sh
BRIDGE_RUN_GUI_SELF_TESTS=1 zsh scripts/test.sh
```

完整自检构造事件对象但不发送它们，使用独立命名剪贴板而不触碰通用剪贴板，并检查输入框布局。沙箱或无图形服务环境可能出现事件分配或剪贴板服务失败，这不应伪装成测试通过。Intel 代码可编译也不等于已在 Intel 实机运行。

## 手工验收

使用可清空的测试输入框，并同时记录 macOS、豆包、UU、两个桥接版本。

1. **本地键盘**：暂停 UU 桥接，在普通本地输入框通过 Fn 开始和结束豆包听写，确认文字落下。希望点击启停时，先确认豆包使用 Fn 免按模式。
2. **本地线控**：启用耳机 1.2，点击中间键开始和结束录音，确认文字落下且不会启动音乐；按住线控不应形成连续多次触发。
3. **纯粘贴**：单独验证 UU 的本地复制 → 远端手动粘贴。
4. **UU 键盘**：启用 UU 2.5.1，在远端空白文本框定位。第一次 Fn 应仅开本地发送框；框内再次 Fn 开始听写，按豆包模式结束。Return 后远端出现本轮文字。默认长按首次 Fn 也应只开框。
5. **UU 线控**：回到 UU 原窗口，第一次线控仅开框；框内下一次线控启动豆包，再点击结束。Return 发送后确认远端文字。必须等发送框出现并获得焦点，再进行下一次点击；确认到达前的极快第二次点击会被忽略。分别测试仅耳机触发、仅键盘触发，以及开框后切换另一种输入方式。
6. **窗口与草稿**：在框内留下手工草稿，切回同一 UU 进程和原窗口再开框，应恢复原文字；切到其他窗口不能悄悄更换旧草稿的发送目标。
7. **生命周期**：多次在本地与 UU 之间切换；菜单打开后关闭；睡眠唤醒；暂停再启用。逐项确认本地 Fn 不受影响、UU 首次开框仍生效、没有重复按键。异常时先记录诊断再重启。
8. **请求失败**：暂停或退出 UU 桥接，再在 UU 前台点击线控。应提示未完成开框，且不补发 Fn 启动豆包。重新启用后再验证一次成功请求。
9. **边界操作**：测试 Esc 取消、中文候选确认、Fn 组合键、发送期间焦点变化，以及两个来源重叠按下。确认没有重复录音、重复发送或残留按键。
10. **可选兼容模式**：开启「兼容模式：长按 Fn 直接听写」并重新启用，单独验证持续录音、松开、转写稳定和远端结果。失败时恢复默认分步模式。

两个自有工具之间的协调无法保证第三方监听器不先消费 Fn，也不能保证所有耳机、输入法或远程版本兼容。报告问题前检查诊断中的设备名、前台应用和本机状态，勿公开真实转写或剪贴板内容。
