# 豆包耳机语音桥接 1.1

把 Mac 的特定 3.5 mm 耳机线控中间键转换为一次 Fn / Globe 点按。它可以独立配合豆包，也可以与本仓库的 UU 远控听写配合使用。

本次发布整理保留原有 1.1 的功能。程序并不输出 Home 键，也不把耳机的按住时长原样转换为 Fn 长按：每次有效中间键按下都会发出约 60 毫秒的 Fn 脉冲。

## 支持范围

只匹配同时满足以下属性的 HID 消费者设备：

| 属性 | 值 |
| --- | --- |
| Product | `Headset` |
| Transport | `Audio` |
| PrimaryUsagePage | `12`（Consumer） |
| PrimaryUsage | `1` |

这是针对 Mac 音频插孔线控接口的实现，**不是通用 USB、蓝牙或所有 3.5 mm 耳机的映射器**。即使耳机接上了，设备属性不同也不会接管。应用的目标最低系统为 macOS 12，实际兼容性仍取决于系统、Mac 与线控设备。

映射启用且辅助功能授权有效后，程序独占打开这个接口。中间键的播放 / 暂停报告不会转发给音乐播放器；音量加减会重新发送，并支持长按重复。设备报告中的其他消费者键不会转发。独占接管覆盖整个匹配接口，即使“仅外置耳机连接时启用”的连接条件尚未满足也会保留接管，以防插入耳机后的首个中间键传给音乐播放器。

暂停映射或退出程序会释放接口。不要同时启用其他抢占同一耳机接口的映射器；接管冲突会显示状态，不会切换成另一种监听方式。

## 构建

在 macOS 上安装 Xcode Command Line Tools 后，在本目录执行：

```sh
bash test.sh
bash build.sh
```

不需要第三方依赖或网络下载。构建生成 `dist/DoubaoHeadsetBridge.app`，包含 Apple Silicon 与 Intel 两个架构。脚本使用项目内 `.build/` 缓存，从干净临时应用包生成结果，并校验应用属性、双架构和临时签名。构建与映射测试都不会启动应用、读取实际线控或发送 Fn。

这里使用 ad-hoc 临时签名，没有 Apple 开发者身份签名或公证；`codesign` 校验成功不代表获得 Gatekeeper 公证。不要通过关闭系统安全机制来安装。可选择自行构建，或按 macOS 提供的“隐私与安全性 → 仍要打开”流程处理可信的构建。

## 安装和权限

1. 退出旧版「豆包耳机语音桥接」。把新生成的应用放到一个固定位置，例如“应用程序”，只启动这一份。
2. 在“系统设置 → 隐私与安全性 → 辅助功能”中添加当前应用并开启，随后重新打开应用。辅助功能用于合成 Fn 和音量事件。
3. 若显示“线控接管未就绪”，按菜单提示授予“输入监控”并重新启动。是否能独占打开这个特定非键盘接口以实际返回结果为准，程序不会仅凭全局输入监控状态拒绝它。
4. 连接目标 3.5 mm 耳机，菜单应显示“音乐控制已拦截”。若连接检测不准确，可取消“仅外置耳机连接时启用”，但这不会扩大 HID 匹配范围。

替换应用或重新构建可能使权限记录失效。若系统开关已开而应用仍显示未授权，完全退出应用，移除旧同名权限条目，再添加当前固定位置的应用，重新启动。不需要重置整个系统权限数据库。

应用不录音，不需要麦克风权限。麦克风由豆包选择，相关权限应授予豆包。程序默认启用映射，并记住“映射启用”和连接条件设置；正常启动只驻留菜单栏，权限或接管异常时会显示设置窗口。

## 独立使用

先在普通本地输入框确认豆包当前的 Fn 设置正常，再测试线控。若使用豆包的“免按模式：Fn”，预期单击线控开始、再单击结束；这是目标用法，是否接受合成 Fn 需要在你的豆包版本上验证。按住 Shift、Control、Option、Command 或 Fn 时，中间键仍被拦截，但不会发送额外 Fn。

## 与 UU 远控听写配合

配合 [UU 远控听写](../uu-voice-bridge/) 的已保留版本时，耳机程序提供的仍是同一个 Fn 短脉冲入口。UU 前台的第一次脉冲可打开发送框；发送框获得焦点后，后续脉冲是否开始 / 结束豆包录音取决于豆包自己的 Fn 模式。按 UU 项目的使用说明完成输入与发送。

不要把“收到 Fn 脉冲”视为“已经开始录音”。当前发布没有宣称一次线控点击就同时开框并自动录音，也没有宣称耳机到远端 Mac 的完整链路已通过实机验收。

## 隐私与限制

- 不联网、不录音、不读取剪贴板、不记录输入文本或逐次按键日志，也不保存按键统计。
- 通过 CoreAudio 枚举本地音频设备以判断耳机连接状态；设置窗口显示授权、连接和接管状态。
- 可执行文件的 `--audio-diagnostics` 参数只输出音频设备状态，不启动映射。输出可能含设备名称；公开反馈前应自行检查。
- 合成 Fn 与物理 Fn 的硬件来源不同，可能被豆包或其他事件监听器忽略。此程序不假冒硬件 HID 设备。
