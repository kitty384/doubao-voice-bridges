# 隐私与权限

## 数据经过哪里

UU 链路为：本地麦克风 → 豆包识别 → 本地发送框 → 系统剪贴板 → UU 文字剪贴板同步 → 远端输入位置。耳机桥接在普通本地输入框或发送框内提供 Fn 脉冲；UU 前台的首次点击发送本机开框消息，不处理声音。

这两个桥接程序没有录音或语音识别能力，没有自行发起网络请求的实现，也不需要麦克风权限。豆包、UU 及系统服务按它们自己的权限和隐私政策工作；不能据此把整条链路描述成离线或不上传音频。

UU 发送框会在内存中保存待发送文字。发送操作覆盖并保留本地系统剪贴板，不恢复旧剪贴板，以免恢复操作再次触发同步并与粘贴竞争。即使后续粘贴取消，已写入的文字也可能仍在剪贴板上，或已被 UU、通用剪贴板、剪贴板历史工具同步、保存。取消发送不撤回这些副本。

## 每个工具使用的能力

| 应用 | 权限或能力 | 用途 |
| --- | --- | --- |
| UU 远控听写 Fn | 辅助功能 | 核对与激活本机 UU 窗口、发送 Command-V，以及兼容长按模式中的合成 Fn |
| UU 远控听写 Fn | 输入监控 | 安装全局 HID 事件过滤器，识别 Fn 及取消条件 |
| 豆包耳机语音桥接 | 辅助功能 | 发送合成 Fn 和音量事件 |
| 豆包耳机语音桥接 | 匹配线控接口的独占访问，必要时输入监控 | 接收并接管特定耳机的消费者按键报告 |
| 豆包语音输入法 | 麦克风及其自身所需权限 | 录音、识别并把文字写入当前本地输入框 |

UU 及豆包的其他权限按各自提示设置。权限授予具体应用，给桥接工具授权不会替代豆包或 UU 的授权。

### UU 的全局过滤范围

启用后，UU 桥接安装的过滤器在全局接收修饰键、按键按下和部分鼠标、滚轮事件。它只在满足前台 UU 条件时开始接管一次 Fn 手势，已接管的按下与松开仍需配对完成；其他事件用于识别组合键或取消当前手势，无关输入放行。因此不能把它描述为“技术上只监听 UU 窗口”。

界面、辅助功能查询和目标核对放在主线程；输入回调在独立线程，不同步等待主线程或调用界面、辅助功能查询。状态检查使用 common run loop mode，避免因菜单交互而暂停检查。进入 UU 时，约 0.15 秒后允许一次有条件的监听刷新：手势须空闲、物理修饰键须松开、目标有效且没有安全输入，并满足至少 3 秒的刷新冷却；旧事件线程完全退出后才启动新监听。程序不周期性争抢监听顺序。系统因超时或用户输入停用监听时，程序仍暂停，等待手动启用。上述措施降低阻塞输入的风险，不保证所有系统和监听器组合下都不会卡顿。

每次启动默认暂停，授权变化不会自动装上监听器。可通过菜单暂停或退出。源码使用实际 Fn / Globe 修饰键事件（键码 `63`），没有把 Fn 改成 Control、F1 或 F10。安全输入和其他键盘工具可能影响事件可见性；系统接受合成 Fn，也不证明豆包一定把它当作自己的听写快捷键。

### 耳机的接管范围

耳机工具仅匹配 `Product=Headset`、`Transport=Audio`、`PrimaryUsagePage=12`、`PrimaryUsage=1` 的接口，不读取键盘或音频流。启用映射后独占整个匹配的消费者接口：中间键不再控制音乐，音量键重新发送，其他消费者用法不会转发。

“仅外置耳机连接时启用”限制 Fn 触发，但条件未满足时仍可能保留接口接管，以避免首个中间键启动播放器。暂停映射或退出程序会释放接口。应用默认启用映射，并记住设置；它与每次启动默认暂停的 UU 工具不同。

## 两个工具之间的本机消息

耳机工具 1.2 在 UU 前台使用 `DistributedNotificationCenter` 请求远控工具 2.5.1 打开发送框；消息只携带随机请求 UUID、目标 UU 进程号和发送时间，回复只携带请求 UUID 和结果状态，不包含音频或转写文字。请求会检查时效、去重和当前目标，确认等待约 0.8 秒，失败不自动补发 Fn。

这是本机进程间协调，并非互联网请求，也不是认证通道。时效与进程检查用于防止过期或重复操作，不构成对同机其他进程的身份认证。消息确认仅表示本地开框结果，不确认豆包录音或远端收件。

## 本地状态与诊断

UU 工具的系统日志记录短随机会话标记、文字长度区间、输入法标记状态、布局和发送状态，不记录转写正文。临时 GUI 状态文件包含进程号、版本、权限、时间、状态文字、Fn 按下与松开计数、过滤器和手势阶段、当前是否允许接管、发送框会话状态；不包含转写正文，正常退出时清理本进程的记录。应用还使用本地单实例锁和用户偏好设置。

UU 的手工诊断输出可能包含前台应用标识和 GUI 进程状态；耳机诊断可能包含本机音频设备名称。耳机工具不保存输入文本、逐次按键日志或按键统计，只保存映射与连接条件设置。公开反馈前，请检查诊断输出；无需附上私人转写文字、完整剪贴板或设备信息。

## 安装、重新构建与权限失效

这两个应用使用 ad-hoc 临时签名，没有 Apple 开发者签名或公证。把应用放在固定位置，只运行一份。替换、移动或重新构建后，macOS 的旧权限记录可能与当前程序不再匹配。

若系统开关已开启而应用仍显示未授权：完全退出对应工具，移除系统设置中的旧同名条目，重新添加当前固定位置的应用，再启动核对。UU 工具需两项权限都生效后手动启用；耳机工具以实际接口接管结果判断是否可用。不需要重置整个权限数据库或关闭系统安全机制。

## 发送确认的边界

发送前程序核对本机 UU 进程、原窗口和剪贴板，再异步发出完整 Command-V 序列。提示“已发送粘贴指令”只表示本机按键已投递，UU 未提供远端实际接收文字的确认。

发送期间切换焦点仍可能造成误贴；请保持原 UU 连接、窗口和远端输入位置有效，不要同时改写剪贴板。发送完成后核对远端文字，尤其避免在密码框或其他敏感位置试验。
