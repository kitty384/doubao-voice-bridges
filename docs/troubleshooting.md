# 排错

先用普通、可清空的文本框测试。每次只验证一个环节，确认后再继续：

1. 暂停或退出两个桥接工具，在本地普通输入框测试豆包自己的 Fn 听写。
2. 只启用耳机桥接，在本地输入框测试线控启停豆包。希望点击启停时，豆包须使用相应的 Fn 免按模式。
3. 在 UU 连接中测试本地复制、远端手动粘贴，确认文字剪贴板同步正常。
4. 启用 UU 桥接：第一次 Fn 开本地发送框，先手工输入并按 Return，确认远端粘贴。
5. 在发送框内测试 Fn 听写，再测试“第一次线控开框、框内后续线控启停听写”。

## 权限已打开，仍提示未授权

UU 工具需要“辅助功能”和“输入监控”分别生效，且启动后默认暂停。系统设置中的同名勾选不保证对应当前构建：

1. 完全退出对应工具，确认没有旧版或其他位置的副本仍在运行。
2. 把当前构建放在固定位置，例如“应用程序”。
3. 在“系统设置 → 隐私与安全性”中移除旧同名条目，再添加当前应用并开启所需权限。
4. 重新启动，在菜单里核对权限；UU 工具再手动点“启用 Fn 听写”。

不要反复重编译后直接覆盖正在运行的应用。终端运行诊断命令时，命令进程的权限也可能与菜单栏 GUI 不同；优先核对 GUI 菜单状态。不需要重置整个系统权限数据库。

## Fn 有时不开框，暂停再启用又恢复

UU 2.5.1 增加了进入 UU 时的一次有条件刷新，以及确认物理 Fn 已释放后清理旧手势的处理。刷新只在空闲且目标有效时尝试，不持续争抢其他工具的监听顺序；系统已停用监听时仍需手动启用。

失效时，先记录当前菜单状态和诊断，再暂停重启，以免清掉现场。诊断中的 `fn_down_count` / `fn_up_count`、`filter_phase`、`gesture_phase`、`eligible` 及会话状态帮助区分原因：

- 按 Fn 后计数不增加：可能事件没有到达桥接，例如其他过滤器先消费事件，或系统安全输入限制事件可见性。
- 计数增加但不能开框：检查前台是否为 UU 连接窗口、当前目标是否有效、是否有未结束手势或原发送框会话。
- 仍有草稿：回到原 UU 进程和原连接窗口再按 Fn，应恢复原草稿；另一窗口不会接管旧草稿的发送目标。
- 显示“监听已停用”或暂停：先处理菜单提示，再手动启用。重复快速启停不是稳定性验收。

菜单显示开启只能说明工具的当前状态，不能保证其他程序会把下一次 Fn 事件传给它。请同时反馈系统、UU、豆包和两个桥接的版本，以及切换窗口、唤醒或打开菜单等复现步骤；无需提供正文。

## Fn 开框后没有录音，或只有豆包浮条

默认流程是 **第一次 Fn 开框，框内再按豆包的 Fn 模式听写，Return 发送**。首次 Fn 即使长按也只开框，开框成功不代表已经录音。

确认 UU 已连接，前台是连接窗口而非设备列表；豆包使用真正的 Fn / Globe，而不是 F1 或 F10。在发送框内点击文本区域，再按 Fn。若仍只有波形而没有文字，核对豆包选择的本地麦克风、录音权限和网络状态。若普通本地输入框也没有转写，先解决豆包本身的输入；不要仅凭波形判断成功。

旧长按流程可从菜单「兼容模式：长按 Fn 直接听写」启用，更改后重新启用监听。它依赖合成 Fn 和焦点切换；失败时使用默认分步流程。不要同时运行多个版本来尝试恢复。

## 线控在本地正常，在 UU 不开框

先确认配套版本为耳机 1.2 / build 3 和 UU 2.5.1 / build 11，且 UU 桥接已手动启用。UU 前台的第一次线控点击直接发送本机开框请求，不再发出 Fn。

若请求未在约 0.8 秒内得到确认，耳机工具提示失败，且不会补发 Fn。这避免请求迟到时又额外触发录音。检查 UU 桥接是否暂停、目标窗口是否有效，以及是否刚切换焦点；确认后重新点击一次。请求确认只代表本地开框，不代表豆包录音。

框内后续线控仍发送约 60 毫秒 Fn。因此若能开框却不能录音，先在普通本地输入框验证线控，再检查豆包的 Fn 免按模式及合成事件兼容性。开框确认到达前的极快第二次点击会被忽略；先确认框已出现并获得焦点，再点击开始听写。

## 框里有文字，远端没有

分步模式需要按 Return 发送；若仍有输入法候选或标记文本，先完成上屏，再按 Return。单独再按 Fn 或线控不会发送。

先手工输入短文本验证：若手工输入也不能远端粘贴，检查 UU 的文字剪贴板同步、远端输入位置和手动 Command-V。发送时松开所有修饰键，保持原 UU 窗口有效，等待同步和粘贴完成。

如果提示目标或剪贴板发生变化，程序会取消自动粘贴，文字保留供确认重试。发送过的文字会保留在系统剪贴板，可等待 UU 同步、确认目标位置后手动粘贴，避免连续重试造成重复文本。

“已发送粘贴指令”不代表远端收件成功；本程序没有远端确认通道。若只出现字母 V，确认运行的是本仓库构建并检查 UU 自身的快捷键传递设置。

## 耳机按键没触发，或音乐仍被播放

查看耳机工具菜单是否显示“音乐控制已拦截”。本版本只接管特定 `Headset` / `Audio` 消费者接口，不能用 USB、蓝牙或不同属性的耳机测试结果推断它可用。

若“线控接管未就绪”，按菜单提示处理输入监控权限并重新启动；退出其他独占线控接口的工具。若只是外置耳机连接识别不准，可临时取消“仅外置耳机连接时启用”，但这不会扩大设备匹配范围。

成功接管也不证明豆包接受合成 Fn。耳机不会长按 Home，也不会把线控按住时长转换成 Fn 长按。按住其他修饰键时中间键被拦截但不触发额外 Fn。先在本地测试，再进入 UU 测试。

## 启用后卡顿或输入异常

先从菜单暂停或退出两个桥接工具；若界面无法操作，用 macOS 的“强制退出”或“活动监视器”结束对应应用。耳机工具退出会释放线控接口，UU 工具暂停会停止监听。确认每个工具只有固定位置的一份应用在运行，再逐一启动测试。

UU 工具每次启动默认暂停，单纯改变权限不会安装监听器；耳机工具会记住映射设置。若尚未启用 UU 监听就出现卡顿，应同时检查耳机映射、旧版程序及其他键盘工具，不能仅凭权限开关认定原因。

UU 事件回调在独立线程，监听刷新等待旧线程完全退出，系统停用后保持暂停。这些措施不构成无卡顿保证。若关闭其他映射工具后仍可复现，请反馈应用版本、系统版本、发生阶段及菜单错误；无需上传私人文字或未经检查的完整诊断。

## 回车发送后 Fn 开不了下一次框，切出再切回 UU 后恢复

2.5.2 针对这个操作顺序修正刷新调度：回到 UU 时发送仍在进行，不应把这一次刷新机会直接丢弃。新版保留有界待处理请求，并在发送清理后明确通知监听器。请在同一个远端输入框重复测试，期间不切本地窗口。

若仍失败，请保留现场，再读取 GUI 诊断中的 `session_state`、`delivery_cleanup_pending`、`eligible`、Fn 到达计数及待处理刷新字段；当前修饰键标志可用于检查是否仍有 Command/Fn 状态。权限已生效或菜单显示已启用，均不能单独证明 Fn 事件已到达本应用。
