# 排错

先用普通、可清空的文本框测试。每次只验证一个环节，确认后再继续：

1. 暂停或退出两个桥接工具，在本地普通输入框测试豆包自己的 Fn 听写。
2. 在 UU 连接中测试本地复制、远端手动粘贴，确认文字剪贴板同步正常。
3. 只启用 UU 桥接：第一次轻按 Fn 开本地发送框，先手工输入并按 Return，确认远端粘贴。
4. 在本地发送框内测试豆包听写，最后再加入耳机桥接。

## 权限已打开，仍提示未授权

UU 工具需要“辅助功能”和“输入监控”分别生效，且启动后默认暂停。系统设置中的同名勾选不保证对应当前构建：

1. 完全退出对应工具，确认没有旧版或其他位置的副本仍在运行。
2. 把当前构建放在固定位置，例如“应用程序”。
3. 在“系统设置 → 隐私与安全性”中移除旧同名条目，再添加当前应用并开启所需权限。
4. 重新启动，在菜单里核对权限；UU 工具再手动点“启用 Fn 听写”。

不要反复重编译后直接覆盖正在运行的应用。终端运行诊断命令时，命令进程的权限也可能与菜单栏 GUI 不同；优先核对 GUI 菜单状态。不需要重置整个系统权限数据库。

## Fn 没反应，或只出现豆包浮条

本仓库的 UU 2.5.0 保留分步操作：**第一次 Fn 开框，框内再按豆包的 Fn 模式听写，Return 发送**。一次点击同时开框并开始录音不在此版本的承诺范围内。

若发送框没有出现，确认 UU 已连接，前台是 UU 的连接窗口而非设备列表；菜单状态为已启用；安全输入没有占用键盘；其他快捷键、映射或远控工具没有同时接管 Fn。可以暂时退出其他映射工具做对比。Fn 是特殊修饰键，不是 F1 或 F10，豆包自身也应设置为 Fn / Globe。

不同监听器可能先于本工具消费事件。可在 UU 已连接后，从桥接菜单暂停一次，再手动启用作对比；程序不会自动不断重装监听来争抢顺序。如果系统报告“监听已停用”，先排除冲突，再由用户手动重新启用。

若只有豆包波形，没有发送框内文字，先轻按开框并点击框内，再使用豆包原生 Fn 操作。核对豆包选择的本地麦克风、录音权限和网络状态。若本地普通输入框也没有转写，先解决豆包本身的输入；不要仅凭波形动画判断转写成功。

长按路径依赖合成 Fn 和输入法焦点切换，失败时先使用分步操作。不要为了触发成功而快速重复开关监听或启动多个版本。

## 框里有文字，远端没有

分步模式需要按 Return 发送；若仍有输入法候选或标记文本，先完成上屏，再按 Return。单独再按 Fn 不会发送。

先手工输入短文本验证：若手工输入也不能远端粘贴，检查 UU 的文字剪贴板同步、远端输入位置和手动 Command-V。发送时松开所有修饰键，保持原 UU 窗口有效，等待同步和粘贴完成。

如果提示目标或剪贴板发生变化，程序会取消自动粘贴，文字保留供确认重试。发送过的文字会保留在系统剪贴板，可等待 UU 同步、确认目标位置后手动粘贴，避免连续重试造成重复文本。

“已发送粘贴指令”不代表远端收件成功；本程序没有远端确认通道。若只出现字母 V，确认运行的是本仓库构建并检查 UU 自身的快捷键传递设置。

## 耳机按键没触发，或音乐仍被播放

查看耳机工具菜单是否显示“音乐控制已拦截”。本版本只接管特定 `Headset` / `Audio` 消费者接口，不能用 USB、蓝牙或不同属性的耳机测试结果推断它可用。

若“线控接管未就绪”，按菜单提示处理输入监控权限并重新启动；退出其他独占线控接口的工具。若只是外置耳机连接识别不准，可临时取消“仅外置耳机连接时启用”，但这不会扩大设备匹配范围。

成功接管也不证明豆包接受合成 Fn。先在本地普通输入框测试单击线控，再测试 UU。每次有效按下只发送约 60 毫秒 Fn，不会长按 Home、持续按住 Fn，也不会单击就同时开框录音。按住其他修饰键时中间键被拦截但不触发额外 Fn。

## 启用后卡顿或输入异常

先从菜单暂停或退出两个桥接工具；若界面无法操作，用 macOS 的“强制退出”或“活动监视器”结束对应应用。耳机工具退出会释放线控接口，UU 工具暂停会停止监听。确认只有固定位置的一份应用在运行，再逐一启动测试。

UU 工具每次启动默认暂停，单纯改变权限不会安装它的监听器；耳机工具会记住映射设置。若尚未启用 UU 监听就出现卡顿，应同时检查耳机映射、旧版程序及其他键盘工具，不能仅凭权限开关认定原因。

当前 UU 代码把事件回调放在独立线程，系统停用监听后保持暂停，不会自动重启。这是防止阻塞和争抢的措施，不是无卡顿保证。若关闭其他映射工具后仍可复现，请反馈应用版本、系统版本、发生阶段及菜单错误；无需上传私人文字或未经检查的完整诊断。
